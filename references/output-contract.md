# 输出契约 v1

仅在核对产物时读取。最终目录恰好包含 final.csv、review_queue.csv、ledger.json。两个 CSV 均为 UTF-8 BOM、标准 CSV 引号转义、CRLF，分别从1连续编号：

```text
序号,项目名称,项目编号,标段名称,标段编号,公司名称,中标与否,投标排名,文件类别,依据文件路径,来源页码,提取方式,证据文本,置信度,复核状态,解析结果生成日期时间
```

业务值有则填、无则空；项目、标段、排名不补造。类别 excel_ledger、提取方式“台账整理”、来源为原文件名、页码空、时间为全任务统一的带时区 ISO 8601。正常提取的记录置信度为1.0，待复核也不降低；仅无法形成 final 记录的独立问题行填0.0。该值不表示中标判断或工商身份概率。

按实际招标组收集并去重中标名单，不按某行是否非空判定。明确对应为“是”；本组名单完整、无未解决名称或读取异常时，其余企业才为“否”。无中标结果留空。原“是否中标”可直接映射，冲突则留空并复核。“未招投标”仅作原文备注和角色审计，不强行清空原表结果。

不使用全局公司名映射。格式清洗仍由程序完成；名称不一致时仅从本组生成最多3个候选，按名称相似度及已有辅助字段排序。模型只收到编号和两个名称，每批最多6对；use_a/use_b/different/uncertain 决定仅作用于本次相关组。只允许选择提供的名称；两个候选同时匹配、一候选同时承接不同中标名、或改名碰撞时不强行合并。无法唯一对应保留复核。最终名称可按已接受决定局部统一，原投标名称/中标名称及修改依据始终保存在 ledger；不向用户逐项询问。

组内重复明细保留全部来源；不同项目/组的参与记录不全局删除。review 复制待复核行，只重编号并在证据前加“原因+换行”；无法形成 final 的问题可独立进入 review。无复核保留表头。两个 CSV 都无记录则失败。

ledger 保存 sources、mapping、projects/groups、records、issues、row_audit、summary、unique_companies、name_pairs/name_decisions 及两个 CSV 的哈希/大小。groups.name_resolutions 记录每个中标名的候选、决定及应用结果；records.corrections 保留修改前后、规则、名称对编号。raw_values 保留原始空白/换行；values 为解析文本。内部 ID 不冒充官方编号；纯名册 project_id=null。

unique_companies 从最终非空公司名按 NFKC、去空白、casefold 去重，保持首次顺序，不额外加入代理或模糊候选；不是确认工商实体数。问题数与复核行数不同。CSV 公式形文本加单引号，csv_text_escapes 可恢复。

run 未完成名称判断时不发布最终三件套，返回 name_review_required、state 和 decisions_path 完整路径（退出码4）。decisions_path 按批次固定在 state 同目录，写入与 resolve 均用此路径；不由模型选择系统临时目录。内部工作状态位于输出目录之外；决定按批次完整校验、原子保存，同批重复提交幂等，冲突提交拒绝。原文件哈希/映射改变或版本不符时拒绝套用旧决定。resume 恢复未完成任务并返回当前批次路径，已发布同任务结果校验后复用。

发布前自动检查表头、枚举、时间、统计、来源、复核关联和企业名单，整批发布到空/新目录。--progress 为可选阶段日志，不规定宿主进度计划。普通处理无需读完整产物；采集接入维护见 [名单契约](spider-contract.md)。
